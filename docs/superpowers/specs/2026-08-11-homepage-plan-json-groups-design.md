# Homepage Plan JSON Groups Design

## 目标

扩展首页 Plan 模块，使其能够按一级分组标题展示计划条目，同时保留方块表示完成状态。计划内容与页面结构分离，后续维护者只需编辑一个 JSON 文件即可增加分组、增加条目、修改文案或切换完成状态。

## 当前状态

首页是直接发布 `docs` 目录的静态站点，没有前端构建步骤。Plan 模块目前包含一个空的 `.plan-list` 和空状态文案；样式表已经定义 `.plan-item`、`.plan-status` 与 `.is-complete`，但页面没有实际计划数据。现有 Python 结构测试明确要求 Plan 不包含条目，这一约束需要随功能一起更新。

## 已确认范围

本次实现包括：

- 新增 `docs/plan.json`，作为 Plan 内容和完成状态的唯一数据来源。
- 在 Plan 模块内展示多个分组；每个分组包含一个标题和一个始终展开的条目列表。
- 使用现有状态方块展示每一项是否完成。
- 在浏览器中加载并渲染 JSON，不引入构建工具或第三方依赖。
- 为加载、异常和无障碍状态提供明确反馈。
- 更新静态结构测试，并新增 Plan 运行时测试。

本次不包括：

- 折叠或展开分组。
- 访客在网页中点击修改完成状态。
- 后台管理界面、表单、数据库或远程内容服务。
- 多级嵌套分组、排序控件、筛选或进度统计。

## 数据模型

`docs/plan.json` 的根节点是一个数组，数组顺序即页面分组顺序。每个分组必须包含：

- `title`：非空字符串，作为分组标题。
- `items`：条目数组，数组顺序即页面显示顺序。

每个条目必须包含：

- `text`：非空字符串，作为显示内容。
- `completed`：布尔值；`true` 表示已完成，`false` 表示未完成。

示例：

```json
[
  {
    "title": "infra",
    "items": [
      {
        "text": "prefill与decode",
        "completed": false
      }
    ]
  }
]
```

渲染器对数据执行完整结构校验。根节点、分组或条目不满足上述模型时，整份数据视为无效并进入统一错误状态，避免页面静默展示不完整的计划。

## 页面结构与渲染

首页继续使用现有的 `Plan` 二级标题。每个数据分组渲染为一个独立的 `.plan-group`：

- 分组标题使用 `<h3 class="plan-group-title">`，保持页面标题层级正确。
- 标题下使用 `<ul class="plan-list">` 承载条目。
- 每个条目使用 `<li class="plan-item">`。
- 状态方块使用 `.plan-status`；完成项在 `<li>` 上增加 `.is-complete`。
- 条目文案使用独立文本元素显示。

`docs/index.html` 只保留 Plan 渲染挂载点和初始状态文案，不复制 JSON 内容。`docs/script.js` 负责以下单一流程：页面初始化时请求数据、校验数据、创建 DOM、替换状态文案。所有数据文本通过 `textContent` 写入，不使用字符串拼接生成 HTML。

计划状态仅供展示，不能点击切换。状态方块提供“未完成”或“已完成”的无障碍名称，使屏幕阅读器无需依赖颜色或填充样式即可理解状态。

## 加载与错误处理

页面初始显示 `Loading plans…`。脚本使用以下请求方式：

```js
fetch("plan.json", { cache: "no-store" })
```

这样可以降低维护者更新 JSON 后浏览器继续展示旧内容的风险。

加载成功且数据有效时，脚本清空挂载点并按 JSON 顺序渲染所有分组。合法的空数组显示现有空状态 `No plans published yet.`。

请求失败、HTTP 响应失败、JSON 解析失败或结构校验失败时，挂载点显示 `Plans are temporarily unavailable.`，具体错误写入浏览器控制台。异常不会阻断首页导航、滚动状态或其他模块。

## 样式

新增样式只服务 Plan 分组：

- `.plan-groups` 控制分组之间的垂直间距。
- `.plan-group-title` 建立 Plan 标题与条目之间的视觉层级。
- 每个分组内的 `.plan-list` 继续沿用现有单列列表样式。
- `.plan-status` 与 `.is-complete` 继续使用现有莫兰迪粉色主题变量。
- 移动端保持单列，不添加额外布局分支。

不改变 Projects、Notes、页头、导航或全站配色。

## 后续维护方式

维护者只编辑 `docs/plan.json`：

- 增加分组：在根数组中增加一个带 `title` 和 `items` 的对象。
- 增加条目：在目标分组的 `items` 数组中增加对象。
- 修改文案：修改对应条目的 `text`。
- 标记完成：把对应条目的 `completed` 从 `false` 改为 `true`。
- 调整顺序：调整数组中分组或条目的顺序。

JSON 必须保持有效语法，字符串使用双引号，最后一个数组元素后不添加多余逗号。

## 测试策略

### Python 静态结构测试

更新 `tests/test_site_structure.py`：

- 移除“Plan 不得包含条目”的旧约束。
- 检查首页存在 Plan 挂载点与状态元素。
- 解析 `docs/plan.json`，断言分组顺序为 `infra`、`llm`。
- 断言每个分组的条目文案和顺序与首次发布内容一致。
- 断言所有首次发布条目的 `completed` 为 `false`。
- 断言 JSON 结构满足数据模型。

### Node.js 运行时测试

新增独立测试执行 `docs/script.js`，使用受控 DOM 与 `fetch` 替身覆盖：

- 成功加载后按顺序渲染分组标题和条目。
- `completed: true` 时增加 `.is-complete` 并提供“已完成”状态说明。
- 合法空数组显示空状态。
- 请求失败、JSON 解析失败和非法结构显示统一错误状态。
- Plan 加载失败时，现有导航初始化仍可正常执行。

### 回归验证

运行现有 Python 与 Node.js 测试套件，确认 Notes、代码渲染和首页模块结构没有回归。最后在本地静态服务器中检查桌面和窄屏页面，确认两个分组常驻展开、状态方块对齐、文案换行正常且控制台没有非预期错误。

## 验收标准

1. 首页 Plan 模块按顺序显示 `infra` 与 `llm` 两个分组。
2. 两个分组下分别显示 13 项和 3 项内容，且不提供折叠控件。
3. 首次发布的 16 个状态方块均显示为未完成。
4. 修改 `docs/plan.json` 后无需修改 HTML 或运行构建命令即可改变页面内容。
5. 把任意条目的 `completed` 改为 `true` 后，该条目显示完成样式和正确的无障碍状态。
6. 数据缺失或无效时，Plan 显示明确错误信息，首页其他功能继续工作。
7. 所有相关自动化测试通过，桌面与移动端布局保持可读。
